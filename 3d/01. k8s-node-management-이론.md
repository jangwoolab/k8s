# Node 관리 - 이론


Kubernetes 관리자가 노드 관리에서 반드시 알아야 할 이론과 명령어를 정리했습니다. Day 2 강의 자료로 바로 쓸 수 있도록 개념과 실무 명령을 함께 담았어요.

## 1. Node란 무엇인가 (이론)

노드는 파드가 실제로 실행되는 워커 머신(물리/가상)입니다. 각 노드에는 세 가지 핵심 컴포넌트가 동작합니다.

- **kubelet**: 컨트롤 플레인의 명령을 받아 파드를 생성·관리하고, 노드와 파드 상태를 API 서버에 보고하는 에이전트
- **kube-proxy**: 노드의 네트워크 규칙을 관리해 Service 트래픽을 파드로 전달
- **컨테이너 런타임**: 실제 컨테이너를 실행 (containerd, CRI-O 등)

컨트롤 플레인은 노드를 "스케줄링 대상 자원"으로 보고, 관리자는 이 노드들의 가용성·용량·상태를 통제하는 것이 핵심 업무입니다.

## 2. Node 상태와 Conditions (이론)

노드 상태는 `STATUS` 컬럼(Ready/NotReady/SchedulingDisabled)으로 요약되지만, 실제 진단은 **Conditions**를 봐야 합니다.

| Condition | True의 의미 |
|---|---|
| `Ready` | 노드가 정상이며 파드를 받을 수 있음 (이것만 정상 시 True, 나머지는 False가 정상) |
| `MemoryPressure` | 노드 메모리가 부족함 |
| `DiskPressure` | 디스크 용량/inode가 부족함 |
| `PIDPressure` | 프로세스 ID가 고갈되어감 |
| `NetworkUnavailable` | 노드 네트워크가 올바르게 구성되지 않음 |

`Ready`를 제외한 Pressure 계열은 **False가 정상**입니다. 이 값들이 True가 되면 kubelet이 파드를 축출(eviction)하거나 스케줄링을 막습니다.

## 3. 스케줄링 통제: Cordon / Drain (이론 + 핵심)

관리자가 노드를 점검·교체할 때 쓰는 가장 중요한 개념입니다.

- **cordon**: 노드를 "스케줄링 불가"로 표시. 기존 파드는 그대로 두되, **새 파드만 안 받게** 합니다.
- **drain**: cordon + 기존 파드를 다른 노드로 **안전하게 이주**(축출). 노드를 실제로 비울 때 사용.
- **uncordon**: 다시 스케줄링 가능 상태로 복귀.

유지보수 표준 워크플로우: `drain → (점검·패치·재부팅) → uncordon`

## 4. Taints & Tolerations (이론)

노드에 **taint(얼룩)**를 찍으면, 그에 맞는 **toleration(허용)**을 가진 파드만 그 노드에 스케줄됩니다. "이 노드는 특정 파드만 받겠다"는 배제 메커니즘입니다.

taint는 세 가지 effect를 가집니다.
- `NoSchedule`: toleration 없는 새 파드는 스케줄 안 됨 (기존 파드는 유지)
- `PreferNoSchedule`: 가능하면 피함 (강제는 아님)
- `NoExecute`: toleration 없는 파드는 즉시 축출됨

컨트롤 플레인 노드에 일반 파드가 안 뜨는 이유가 바로 `node-role.kubernetes.io/control-plane:NoSchedule` taint 때문입니다.

> **taint vs cordon 구분**: cordon은 "모든 새 파드 차단"(전체 차단), taint는 "특정 조건의 파드만 선별 허용/배제"입니다.

## 5. Labels & nodeSelector / Affinity (이론)

노드에 라벨을 붙이면 파드를 특정 노드에 유도할 수 있습니다.
- **nodeSelector**: 가장 단순한 방식. 파드가 특정 라벨을 가진 노드에만 배치됨
- **node affinity**: 더 유연한 조건(필수/선호, 표현식)을 지정
- taint/toleration이 "노드가 파드를 거부"하는 쪽이라면, affinity/selector는 "파드가 노드를 선택"하는 쪽입니다.

## 6. Capacity vs Allocatable (이론)

`kubectl describe node`에서 보이는 두 값의 차이를 알아야 합니다.
- **Capacity**: 노드의 전체 물리 자원
- **Allocatable**: 시스템 데몬(kubelet, OS) 몫을 제외하고 **파드가 실제 쓸 수 있는** 자원

스케줄러는 Allocatable을 기준으로 파드를 배치합니다.

## 노드 관리 명령어

### 조회 / 진단

```bash
# 노드 목록 (상태, 역할, 버전)
kubectl get nodes

# 더 자세히 (IP, OS, 커널, 런타임 버전)
kubectl get nodes -o wide

# 특정 노드 상세 — Conditions, Capacity/Allocatable, taint, 배치된 파드, 이벤트
kubectl describe node <노드명>

# 노드 리소스 사용량 (metrics-server 필요)
kubectl top node
kubectl top node <노드명>

# 특정 노드에서 실행 중인 모든 파드 조회
kubectl get pods -A -o wide --field-selector spec.nodeName=<노드명>

# 라벨까지 함께 표시
kubectl get nodes --show-labels
```

### 스케줄링 통제 (유지보수 핵심)

```bash
# 새 파드 차단 (기존 파드는 유지)
kubectl cordon <노드명>

# 노드 비우기 — 파드를 다른 노드로 이주
kubectl drain <노드명> \
  --ignore-daemonsets \         # DaemonSet 파드는 이주 대상에서 제외(필수)
  --delete-emptydir-data        # emptyDir 데이터가 있는 파드도 축출 허용

# 점검·패치·재부팅 후 다시 스케줄링 허용
kubectl uncordon <노드명>
```

> `drain`은 `--ignore-daemonsets`가 거의 항상 필요합니다(DaemonSet은 모든 노드에 떠야 하므로 이주 불가). PodDisruptionBudget이 설정돼 있으면 drain이 그것을 존중하며 진행합니다.

### 라벨 / 어노테이션

```bash
# 라벨 추가
kubectl label node <노드명> disktype=ssd

# 라벨 변경(덮어쓰기)
kubectl label node <노드명> disktype=nvme --overwrite

# 라벨 제거 (키 뒤에 -)
kubectl label node <노드명> disktype-

# 어노테이션 추가
kubectl annotate node <노드명> example.com/owner=team-a
```

### Taint 관리

```bash
# taint 추가 — key=value:effect 형식
kubectl taint nodes <노드명> dedicated=gpu:NoSchedule

# taint 제거 (끝에 -)
kubectl taint nodes <노드명> dedicated=gpu:NoSchedule-

# 컨트롤 플레인 taint 제거 (단일 노드 실습 시)
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
```

### 노드 디버깅

```bash
# 노드에 디버그용 파드를 띄워 호스트 파일시스템 접근
kubectl debug node/<노드명> -it --image=busybox

# kubelet 로그 (노드에 SSH 접속 후, systemd 환경)
journalctl -u kubelet -f

# 노드의 kubelet/런타임 상태 (노드에서)
systemctl status kubelet
sudo crictl ps          # 노드에서 실행 중인 컨테이너 (containerd)
sudo crictl pods        # 노드의 파드 샌드박스
```

### 노드 제거 (클러스터에서 분리)

```bash
# 1) 비우기
kubectl drain <노드명> --ignore-daemonsets --delete-emptydir-data
# 2) 클러스터에서 삭제
kubectl delete node <노드명>
# 3) 해당 노드에서 kubeadm 상태 초기화
sudo kubeadm reset -f
```

## 표준 유지보수 워크플로우 (정리)

노드 1대를 점검·재부팅하는 전형적인 순서입니다.

```bash
kubectl drain k8s-worker01 --ignore-daemonsets --delete-emptydir-data
# → 노드에서 OS 패치 / 재부팅 / 하드웨어 점검 수행
kubectl uncordon k8s-worker01
kubectl get nodes        # Ready 복귀 확인
```

이 흐름(drain → 작업 → uncordon)과 Conditions 읽는 법, taint/cordon의 차이만 확실히 잡으면 노드 관리의 80%는 커버됩니다.
